### 1. Scope & Architectural Boundaries

This version implements the final technical hardening for the AURUM execution pipeline:
- **Phase B — Reference-Bound Structural Episode**: Enforces strict reference node resolution (`resolve_verified_reference_node`) from authoritative swings and closed bars. Rejects ambiguous references with identical price across distinct timestamps (`AMBIGUOUS_REFERENCE_PRICE`), future-known references (`REFERENCE_KNOWN_AFTER_DECISION`), and invalid non-positive timestamps (`INVALID_REFERENCE_TIMESTAMPS`). Completely removes caller-supplied boundary overrides (`episode_start_ms`) to prevent arbitrary timestamps from corrupting derived structure.
- **Phase C — Break Validation and Causal Evidence**: Replaces permissive `except Exception: pass` paths with `resolve_verified_break_candle`. Enforces strict close-through: `break_close < reference_price` for SHORT and `break_close > reference_price` for LONG. Rejects wick-only penetration and equality. Enforces source candle provenance in `closed_bars`, OHLC sanity, and confirmation cutoff before decision time.
- **Phase D — Protected Origin, ATR and Stop Loss**: Enforces episode membership `[episode_start_ms, episode_end_ms)` via `validate_episode_interval` and `validate_protected_origin_binding`. Isolates multi-leg structures: pivots occurring at or after subsequent references are strictly excluded (`ORIGIN_AFTER_EPISODE_END`). Directional selection picks the highest swing high for SHORT and lowest swing low for LONG, impervious to older lookback noise.
- **Phase E — Financial Authority and True Cost Parity**: Implements `build_verified_cost_context` and `assert_order_financial_parity`. Replaces ambiguous `.first()` queries on `models.SystemConfig` with deterministic key precedence (`["slippage_usd", "slippage", "default_slippage"]`, etc.). Preserves explicit `0.0` slippage without falling back to defaults. Strictly validates finite non-negative numbers and rejects malformed/negative slippage and fees. Post-ARM orders strictly honor frozen snapshots. Fail-closed at ARM: candidates with unavailable cost context are rejected with `COST_CONTEXT_UNAVAILABLE`.
- **Phase F & G — Full Cycle ARM and Paper Execution**: Implements pure ARM invariant validation `validate_arm_invariants` checking quantity, stop consistency, daily fill cap, quote validity, trigger expiry, and LONG/SHORT price geometry. Enforces ARM idempotency so repeated evaluation ticks never duplicate paper orders.
- **Phase H — Frontend Chart Evidence**: Expanded Playwright browser verification in `frontend/tests/e2e/v17_5_6_chart_evidence.e2e.ts` (test `P06`) proving persistent financial parity and chart overlay stability.
- **Phase J — Acceptance Runner and Clean Provenance**: Implemented `tools/run_v17_5_8_acceptance.py` executing all 14 gates, dynamically parsing JUnit XML and Vitest outputs, computing SHA-256 source fingerprints across all critical implementation files, and generating clean acceptance records without circular commit SHA dependencies.

### 3. Observed Defects vs. Suspected Risks

- **Observed Defect 1 (Eliminated)**: `stop_placement_service.py` line 1244 had `except Exception: pass` around break candle OHLC parsing. Unreadable or malformed break candles could silently proceed to origin search. **Fixed**: Replaced with `resolve_verified_break_candle` which strictly validates candle OHLC and returns `BREAK_CANDLE_INVALID`.
- **Observed Defect 2 (Eliminated)**: Ambiguous `.first()` query on `models.SystemConfig` with candidate key sets in `evaluate_cycle`. Database row ordering could result in `default_slippage` being picked instead of `slippage_usd`. **Fixed**: Extracted `get_system_config_cost_value` with deterministic priority queue matching `["slippage_usd", "slippage", "default_slippage"]`.
- **Observed Defect 3 (Eliminated)**: In `_arm_paper_candidate`, if `cost_ctx.get("available")` was False, the code fell back to calculation slippage and proceeded to ARM. **Fixed**: Enforced strict fail-closed check: if cost context is unavailable, candidate is rejected with `COST_CONTEXT_UNAVAILABLE`.
- **Suspected Risk 4 (Eliminated)**: Caller-injected `episode_start_ms` in `resolve_episode_membership_from_structure`. A caller could pass an arbitrary timestamp that exists in `closed_bars` and redefine the derived episode. **Fixed**: Caller boundary authority was completely removed; episode start is strictly derived from the verified reference occurrence.
