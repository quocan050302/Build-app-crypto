## 1. Executive Summary

AURUM Desk V17.9.0.1.3 R1 was previously reported with `VERIFIED_FOUNDATION_CLOSURE`, 107/107 passed gates, 95/95 negative controls, and 210 verified 5-way comparisons. However, an independent audit identified four critical release-blocking evidence-integrity defects:

1. **P0-A:** Historical Production decisions generated by the baseline oracle contained hardcoded / inferred placeholder fields (`qty_val = 0.34`, `uni_val = 'VALID'`, `anchor_kind = 'STRUCTURAL_SWING'`, `dec_id = f'dec_{model_id}_{ts_ms}'`) and approximate substring matching (`model_id in str(r.opportunity_id)`) rather than authentic downstream consumption event lineage.
2. **P0-B:** Cross-runtime canonical hashing reused `shared_ctx`, `p_in`, and `cycle_cfg` across runtimes instead of capturing and hashing the actual inputs entering independent runtime boundaries; the canonical artifact `V179013_R1_INDEPENDENT_RUNTIME_INPUT_HASHES.json` on disk was an empty JSON object `{}`.
3. **P0-C:** The acceptance verdict engine (`tools/acceptance_verdict.py`) had fail-open fallback defaults converting missing or corrupted evidence into `PASS` (e.g., `hist_st = "PASS"` when manifest was missing; `neg_passed = 95` when negative controls report was missing; `disk_st = "PASS"` with 50 GB free when disk report was missing; and `VERDICT_STRATEGY_PERFORMANCE` hardcoded to `PASS` even with missing backtest metrics).
4. **P0-D:** Exact-source acceptance was violated: the tested source commit SHA (`21cc6876cd9e2a846adf96d22a4d2061b8bf4e98`) differed from the backtest source commit SHA (`2a494323d87f0417fbc2b118f26c788a07140672`), and this contradiction was not rejected by the acceptance verifier.

All four defects have been reproduced on the actual repository code.

- **Reproduction Procedure:**
  Inspect lines 2520–2575 in `backend/services/v17_9_0_1_baseline_oracle.py`:
  ```python
  cand_id = f'cand_{model_id}_{ts_ms}' if cand_summary.get('is_eligible') else None
  dec_id = f'dec_{model_id}_{ts_ms}'
  ...
  elif cand_summary.get('is_eligible'):

      entry_ref = cand_summary.get('planned_entry')
      sel_sl = cand_summary.get('stop_loss')
      leg_sl = cand_summary.get('stop_loss')
      tp_val = cand_summary.get('take_profit')
      uni_val = 'VALID'
      anchor_kind = 'STRUCTURAL_SWING'
      net_rr_val = ...
      qty_val = 0.34
      fvg_id = None; brk_id = None; swp_id = None
      ep_id = f'ep_{model_id}_{ts_ms}'; anc_id = f'anc_{model_id}_{ts_ms}'; inv_px = sel_sl
  ```
  And downstream consumer matching:
  ```python

  ```
- **Observed Result:**
  Authoritative neutral records in `BASELINE_DECISIONS.jsonl` and `V179013_R1_HISTORICAL_CONSUMED_DECISION_LINEAGE.jsonl` contained hardcoded `0.34` quantity, assumed `"STRUCTURAL_SWING"` anchor kind, and assumed `"VALID"` unicorn validity, irrespective of whether the original historical candidate had those values or whether an order was actually armed.
- **Expected Result:**
  Authentic downstream decision values must come strictly from the original historical candidate or downstream consumer (`cand_out.calculation.quantity`, `cand_out.stop_placement.anchor_kind`, `cand_out.unicorn_evidence`). If no quantity was computed or no order was armed, quantity must be `None` (not 0.34). Decision and candidate IDs must be grounded in authentic event identities (`candidate_key`, `armed_order.id`, `armed_order.client_order_id`), and correlation IDs must be explicitly distinguished. Substring matching `model_id in str(opportunity_id)` must be replaced with authentic candidate key and opportunity record linkage.
- **Root Cause:**
  Over-simplification in the historical subprocess harness: `cand_summary` originally extracted only 5 primitive keys, discarding the candidate's authentic calculation, stop placement, and unicorn evidence objects, and substituted synthetic placeholders.
- **Minimal Implementation Fix:**
  Extract full authentic attributes from `cand_out` (and `cg_out`):
  1. Retrieve `cand_out.candidate_key` as `cand_id`.
  2. Retrieve authentic `calculation.quantity` and `calculation.net_rr` from `cand_out` when present; if absent or uncalculated, set to `None`.
  3. Retrieve authentic `stop_placement.anchor_kind`, `anchor_id`, `invalidation_price`, and `protective_distance` from `cand_out.stop_placement`.
  4. Retrieve authentic `unicorn_evidence.unicorn_validity` (or evaluate breaker block overlap) from `cand_out.unicorn_evidence`.
  5. In orchestrator consumption, link candidates to funnel records via exact `candidate_key` / `opportunity_id` match. If an order was armed, extract authentic `armed_order.id` and `armed_order.quantity`.
  6. Disallow synthetic IDs from masquerading as authoritative historical Production IDs.
- **Regression Risks:**
  Parity comparisons might detect subtle differences if refactored evaluators expect `None` while historical baseline previously emitted `0.34` or `"STRUCTURAL_SWING"`. These differences must be classified truthfully as `EXPECTED_DOCUMENTED_CHANGE` or `NOT_COMPARABLE`.
- **Required Negative Tests:**
  Injected scenario where candidate is marked consumed with fixed quantity `0.34` without downstream order -> MUST FAIL. Injected scenario where candidate matches by model substring only -> MUST FAIL.

### 2.2 DEFECT P0-B: Cross-Runtime Canonical Hashing Reusing Shared Contexts

- **Actual Source File:** `tools/generate_v17_9_0_1_artifacts.py`
- **Function and Caller:** `compute_cross_runtime_parity_report()` invoked by `generate_v17_9_0_1_release_artifacts()`.
- **Reproduction Procedure:**
  Inspect lines 731–760 in `tools/generate_v17_9_0_1_artifacts.py`:
  ```python
  base_in = base_snap.get("market_input") or shared_ctx
  base_cfg = base_snap.get("config") or cycle_cfg
  shared_snap_clean["canonical_semantic_input_hash"] = compute_canonical_semantic_input_hash(shared_ctx)
  p_in = shared_ctx
  p_snap_clean["canonical_semantic_input_hash"] = compute_canonical_semantic_input_hash(p_in)
  s_snap_clean["canonical_semantic_input_hash"] = compute_canonical_semantic_input_hash(p_in)
  bt_snap_clean["canonical_semantic_input_hash"] = compute_canonical_semantic_input_hash(shared_ctx)
  ```
  And line 2804:
  ```python
  _write_lf_bytes(vd / "V179013_R1_INDEPENDENT_RUNTIME_INPUT_HASHES.json", json.dumps(hist_replay.get("independent_runtime_hashes", {}), indent=2) + "\n")
  ```
  Inspect on-disk artifact `aurum-desk/docs/v17_9_0_1_3/V179013_R1_INDEPENDENT_RUNTIME_INPUT_HASHES.json` -> content is `{}`.
- **Observed Result:**
  All five runtimes computed canonical input hashes from the exact same Python object `shared_ctx` and `cycle_cfg`. Furthermore, the published artifact `V179013_R1_INDEPENDENT_RUNTIME_INPUT_HASHES.json` was an empty dictionary `{}`.
- **Expected Result:**
  Each of the five runtimes must capture its own actual consumed inputs and configuration at its distinct boundary:
  1. `HISTORICAL_PRODUCTION`: Captured at historical subprocess input boundary.
  2. `SHARED_STRATEGY_EVALUATOR`: Captured at `SharedStrategyEvaluator.evaluate_decision()` entry.
  3. `PRODUCTION`: Captured at `ScalpWatcherOrchestrator.evaluate_cycle()` entry.
  4. `MARKET_SHADOW`: Captured at `MarketShadowService.evaluate_shadow_cycle()` entry.
  5. `CHRONOLOGICAL_BACKTEST`: Captured at `evaluate_production_parity_model_snapshot()` / simulation entry.
  The artifact `V179013_R2_INDEPENDENT_RUNTIME_INPUT_HASHES.json` must be fully populated with 5 verifiable source records per scenario. An empty artifact must cause immediate acceptance failure.
- **Root Cause:**
  `compute_cross_runtime_parity_report` assigned `p_in = shared_ctx` and passed `shared_ctx` to all five hash functions for convenience, bypassing runtime capture instrumentation. In addition, the dictionary `hist_replay["independent_runtime_hashes"]` was not populated.
- **Minimal Implementation Fix:**
  Instrument/extract the authentic captured input snapshot and configuration dict from each runtime's own execution output:
  - Historical: from isolated execution output dictionary.
  - Shared: from `market_snapshot` and `structural_context`.
  - Production: from orchestrator cycle context (`shared_cycle_input_snapshot_hash`, candle buffers, quote).
  - Shadow: from shadow service input payload.
  - Backtest: from backtest runner opportunity extraction context.
  Compute canonical hashes independently, verify non-empty hash records across all five runtimes, and populate `V179013_R2_INDEPENDENT_RUNTIME_INPUT_HASHES.json`.
- **Regression Risks:**
  If any runtime receives slightly different timestamps, float precisions, or extra keys, canonical hashing will detect the divergence.
- **Required Negative Tests:**
  Injected OHLC modification in one runtime -> MUST FAIL parity and input provenance check. Injected empty independent runtime hashes artifact -> MUST FAIL acceptance. Shared-context pointer substitution -> MUST FAIL provenance check.

### 2.3 DEFECT P0-C: Acceptance Verifier Fail-Open Defaults

- **Actual Source File:** `tools/acceptance_verdict.py`
- **Function and Caller:** `derive_authoritative_acceptance_verdicts()` and `verify_persisted_acceptance_artifacts()`.
- **Reproduction Procedure:**
  Execute `derive_authoritative_acceptance_verdicts()` with missing evidence:
  ```python
  derive_authoritative_acceptance_verdicts(
      gate_results={'tested_source_sha': 'test_sha'},
      parity_report={'status': 'PASS', 'five_way_verified_count': 210, 'unexpected_divergence_count': 0},
      negative_results=None,  # Missing!
      backtest_metrics=None,  # Missing!
      disk_report=None,       # Missing!
      phase_b_manifest=None,  # Missing!
      final_code_sha='test_sha'
  )
  ```
- **Observed Result:**
  ```text
  VERDICT_HISTORICAL_BASELINE: PASS
  VERDICT_NEGATIVE_CONTROLS: PASS
  VERDICT_ASYNC_AND_DISK_SAFETY: PASS
  VERDICT_STRATEGY_PERFORMANCE: PASS
  ```
  The verifier returned `PASS` on 4 out of 5 checks despite every underlying evidence artifact being `None`.
- **Expected Result:**
  Missing evidence must strictly fail closed: return `FAIL` or `BLOCKED_BY_MISSING_EVIDENCE`.
  No optimistic default strings or numbers.
- **Root Cause:**
  Defensive coding in `tools/acceptance_verdict.py` lines 1757, 1804–1807, 1837–1839, 1852–1864 used fallback defaults (`"PASS"`, `95`, `50_000_000_000`, `PASS`) to avoid `KeyError` / `AttributeError`, inadvertently converting missing files into release approvals.
- **Minimal Implementation Fix:**
  Replace all optimistic fallback defaults with strict fail-closed validation:
  1. `phase_b_manifest` missing or empty -> `hist_ok = False`, status `"FAIL"`, explanation `"MISSING_HISTORICAL_BASELINE_MANIFEST"`.
  2. `negative_results` missing or empty -> `neg_ok = False`, status `"FAIL"`, explanation `"MISSING_NEGATIVE_CONTROLS_REPORT"`.
  3. `disk_report` missing or empty -> `async_ok = False`, status `"FAIL"`, explanation `"MISSING_DISK_GUARD_REPORT"`.
  4. `backtest_metrics` missing or empty -> `perf_ok = False`, status `"FAIL"`, explanation `"MISSING_BACKTEST_METRICS"`.
  5. In `verify_persisted_acceptance_artifacts()`, add all mandatory R2 artifacts to `mandatory_files`.
- **Regression Risks:**
  Any test that calls `derive_authoritative_acceptance_verdicts` with incomplete mocks will now fail unless full, valid mock payloads are provided.
- **Required Negative Tests:**
  Deliberately omit `phase_b_manifest`, `negative_results`, `disk_report`, `backtest_metrics`, and `independent_runtime_hashes` individually -> each MUST produce overall status `FAIL` / `BLOCKED`.

### 2.4 DEFECT P0-D: Backtest Source SHA Differs from Tested Source SHA

- **Actual Source File:** `tools/acceptance_verdict.py`, `tools/run_v17_8_acceptance.py`, and `docs/v17_9_0_1_3/V179013_R1_EXACT_SOURCE_MANIFEST.json`.
- **Function and Caller:** `derive_authoritative_acceptance_verdicts()` and acceptance manifest generation.
- **Reproduction Procedure:**
  Inspect `V179013_R1_EXACT_SOURCE_MANIFEST.json`:
  ```json
  {
    "final_code_sha": "21cc6876cd9e2a846adf96d22a4d2061b8bf4e98",
    "backtest_source_sha": "2a494323d87f0417fbc2b118f26c788a07140672",
    "status": "PASS"
  }
  ```
  Pass these conflicting SHAs into `derive_authoritative_acceptance_verdicts()`:
  `overall_status` evaluates to `"PASS"` and verdict evaluates to `"VERIFIED_FOUNDATION_CLOSURE"`.
- **Observed Result:**
  The verifier allowed a backtest executed on commit `2a49432...` to be certified as part of a release tagged with executable SHA `21cc687...`.
- **Expected Result:**
  All mandatory final regression, parity, and chronological backtest evidence must be generated from the **exact same frozen executable commit**. Any divergence between `final_code_sha` and `backtest_source_sha` must block acceptance (`BLOCKED_BY_EXACT_SOURCE_MISMATCH`).
- **Root Cause:**
  `derive_authoritative_acceptance_verdicts()` verified `tested_sha == final_code_sha` for gate results, but did not assert that `backtest_source_sha == final_code_sha`.
- **Minimal Implementation Fix:**
  1. Add strict assertion: `backtest_source_sha == final_code_sha` in `derive_authoritative_acceptance_verdicts()` and `validate_semantic_acceptance_bundle()`.
  2. Implement code freeze workflow: apply R2 fixes, run preliminary tests, commit code changes to establish a single immutable frozen commit SHA, and run both full regression and the chronological backtest on that exact frozen commit.
- **Regression Risks:**
  Requires re-running the chronological backtest whenever code changes, preventing stale artifact promotion.
- **Required Negative Tests:**
  Injected backtest source SHA mismatch -> MUST FAIL release acceptance with diagnostic error.
