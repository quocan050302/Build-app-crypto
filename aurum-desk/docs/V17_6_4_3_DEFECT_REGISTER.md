# AURUM DESK V17.6.4.3 — DEFECT REGISTER
## Telemetry Isolation, Evidence Authority, Durable Identity & Acceptance Integrity

| ID | Priority | Defect Title | Impact & Vulnerability Path | Status |
|---|---|---|---|---|
| **DBEA-01** | **P0** | Shared pending queue may write intervals to the wrong database | `ObservationIntervalService.persist_pending_intervals()` iterates over the global singleton `_pending_intervals` without checking the database identity of the target session. If Session B flushes, uncommitted intervals from Database A can be persisted into Database B. | OPEN |
| **DBEA-02** | **P0** | Active interval state is not scoped to database identity | `self._active_intervals` key `(run_id, symbol, scope, worker_role, evidence_origin, engine_instance_id)` omits database identity. Producers writing to separate database files sharing the same run ID collide in memory. | OPEN |
| **DBEA-03** | **P0** | GOOD quality can bypass authoritative quote validation | `EngineObservabilityService.record_engine_heartbeat()` accepts boolean flags (`transport_state == 'CONNECTED'`, `is_feed_healthy == True`, `is_quote_fresh == True`, `quote_age_sec <= 2.0`) without requiring an authoritative Bid/Ask quote and timestamp. | OPEN |
| **DBEA-04** | **P0** | Typed/dictionary evidence objects can authorize unsupported GOOD | Metadata containing `{"evidence_quality": {"quality": "GOOD"}}` or an unverified instance of `ObservationEvidenceQuality(quality="GOOD")` is trusted directly by `record_engine_heartbeat()`. | OPEN |
| **DBEA-05** | **P1** | RAM interval identity differs from persisted identity | `_make_pending_key()` uses `engine_instance_id`, `evidence_origin`, and `mode`, but `PaperObservationInterval` SQL schema omits `engine_instance_id` and `evidence_origin`. Duplicate lookup queries fewer dimensions. | OPEN |
| **DBEA-06** | **P1** | Duplicate detection is not protected by matching database uniqueness | `paper_observation_intervals` table lacks a database-enforced unique constraint or deterministic `interval_identity` index, leading to race-condition duplicate inserts. | OPEN |
| **DBEA-07** | **P1** | Persistence health can be inferred from historical rows | `build_observation_dashboard_snapshot()` sets `evidence_persistence_status = "COMMITTED"` if historical cycle and interval rows exist, even if the worker is offline or current interval collection is stalled. | OPEN |
| **DBEA-08** | **P1** | Pending/error metrics can leak between DB contexts | `get_pending_metrics()` aggregates global pending counts and errors without database scoping, exposing Database A failures in Database B dashboards. | OPEN |
| **DBEA-09** | **P1** | Borrowed session may report COMMITTED after flush | Telemetry writes on a borrowed `Session` perform `flush()` without an owned transaction commit, potentially reporting `COMMITTED` before transaction completion or causing premature business commit. | OPEN |
| **DBEA-10** | **P1** | Full backend acceptance uses a manually curated file list | Gate `G22_full_backend_tests` in `run_v17_6_4_2_acceptance.py` executed a static list of 29 test files rather than dynamic discovery across all `backend/tests`. | OPEN |
| **DBEA-11** | **P1** | Scheduler integration coverage is not independently proven | Scheduler evaluation and heartbeat paths require independent verification with isolated SQLite engines and canonical feed proofs. | OPEN |
| **DBEA-12** | **P1** | Source, schema and acceptance evidence need final reconciliation | Acceptance runner must verify clean worktree, identical tested/remote SHA, artifact checksums, and strict zero-bypass evaluation. | OPEN |
